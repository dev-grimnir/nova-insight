## Recent work

### Chart aggregation threshold bug (canvas width measured before Chart.js mounts)
**File:** `src/views/nova-snapshot-chart.js`

`canvas.clientWidth` returns 300 (HTML default) before Chart.js sizes the canvas. This made `minVisibleMs` ~4x too large on wide containers, silently aggregating events shorter than ~72 minutes on month-scale views.

**Fix:** Use `canvas.parentElement?.clientWidth` instead — the parent container already has its CSS layout width before Chart.js runs.

    const canvasWidth = canvas.parentElement?.clientWidth || canvas.clientWidth || 1200;

### Chart height + padding reduction (eliminated modal scrollbar)
**Files:** `src/views/nova-snapshot-panel-view.js`, `src/views/nova-snapshot-chart.js`

Dead space above the chart data came from `layout.padding.top: 30` (no top-axis labels, so pure wasted air) combined with `CHART_HEIGHT_PX = 320`. Reduced to `top: 10` and `260px` respectively. Eliminated the scrollbar in the snapshot modal.

### Tooltip coordinate mismatch fix (scale-95 on modal box)
**File:** `src/views/nova-snapshot-view.js`

Root cause: modal inner box had Tailwind `scale-95` class permanently applied — never removed, so the canvas was always visually at 95% while Chart.js used 100% coordinates. ~5% rightward offset (~3 min on a 59-min chart).

**Fix:** Removed Tailwind scale class. Inner box now uses `style="transform:scale(0.95)"` and animates to `scale(1)` via double `requestAnimationFrame`. Added `id="snapshot-modal-box"` for JS targeting.

**Rule:** NEVER use a Tailwind scale class on the modal box. The animation must be inline style only.

### Tooltip period lookup fix
**File:** `src/views/nova-snapshot-chart.js`, `#mountCustomTooltip`

Replaced `chart.scales.x.getValueForPixel()` with direct linear interpolation to avoid Chart.js internal translation artifacts. Added exclusive-end boundary so the cursor at a period transition resolves to the later period, not the outgoing one.

    var t = (mouseX - pxLeft) / (pxRight - pxLeft);
    var cursorMs = xScale.min + t * (xScale.max - xScale.min);

### Syntax error fix in nova-snapshot-chart.js
**File:** `src/views/nova-snapshot-chart.js`

Extra closing brace in the `plugins` block pushed `scales` and `layout` outside `options`, causing `SyntaxError: missing ) after argument list` at line ~4746 of the Tampermonkey bundle. Fixed by collapsing to a single `},` that correctly closes only `plugins`.

### Uptime color-coding in snapshot ribbon
**File:** `src/views/nova-snapshot-panel-view.js`, `#buildRibbon`

    const uptime = parseFloat(this.model.getUptimePercent());
    const uptimeColor = uptime >= 75 ? 'text-emerald-400' : uptime >= 60 ? 'text-yellow-400' : 'text-red-400';

### demo index.html missing script tag
**File:** `index.html` on demo branch

`NovaSnapshotPanelView` was not loaded — `nova-snapshot-panel-view.js` script tag was missing. Added between `nova-snapshot-chart.js` and `nova-snapshot-view.js`.

**Rule:** demo's `index.html` manually lists every `<script>` tag in load order (same order as Tampermonkey @require directives). Any new view/model/controller file added to the project MUST also be added to index.html on the demo branch.

## Architectural decisions

- **`NovaSnapshotPanelView`** is the shared snapshot paradigm (header ribbon + canvas + drill-down wiring). Composed into `NovaSnapshotView` (modal wrapper) and `NovaReportSnapshotView` (inline). Views are dumb — no data fetching.
- **`NovaSnapshotController`** owns the history stack. `drillTo` is a pure transform (no HTTP) — operates on parent model's already-fetched events. `buildFromEvents` and `buildData` both filter events to `[startDate, endDate]` before the analyzer call.
- **No destroy methods** anywhere in the snapshot system. Chart instances die with their DOM; GC handles it.
- **`NovaAnalyzer.#computeLeadTime`** injects an opposite-status boundary event at `requestedStart` when the first real event is after the window start. This is data, not presentation — parent models store events including the boundary; drill-downs inherit that and get their own sub-window boundary.
- **`NovaSnapshotChart` period-building is internal.** `#buildPeriods` and `#aggregatePeriods` stay private.
- **`canvas.clientWidth` is unreliable before Chart.js mounts.** Always use `canvas.parentElement?.clientWidth` for any pre-mount width measurement.

## Latent bugs identified but not fixed

### `NovaHTTPController.#buildPaginationParams` silent time-of-day override
**File:** `src/controllers/nova-http-controller.js`

When `paginateReportLogs` is called with explicit `startDate`/`endDate` but null hour/min args, `#buildPaginationParams` silently forces `shour=0, smin=0` and `ehour=23, emin=59`. This widens the fetch window beyond what the caller requested. The snapshot controller is defended via window-filtering in `buildData` and `buildFromEvents`, but the bug remains for any other caller of `paginateReportLogs`.

**Fix when ready:** Read `sDate.getHours()` / `sDate.getMinutes()` when explicit args are null; fall back to 0/0 only when no `startDate` was passed at all.

### Duplicate toast on Account Not Found
`updateCustomerStatus` (dashboard controller) AND `tabController.add` both fire a 'Customer not found in RADIUS' toast on the same condition. Fix: remove the toast from `tabController.add`, keep the customer-remove. `updateCustomerStatus` owns the messaging.

### `getLatestEntry` backward-walk early-exit
**File:** `demo/nova-http-controller-synthetic.js`

Loop walks events array backward. `t < cutoff` does `break` — should `continue`. Practically masked by progressive-lookback widening but semantically wrong.

### Cleanup in `NovaHTTPController`
- `paginateReportLogs` has a dead `const last = entries[entries.length - 1]` (assigned, never used).
- `#parsePageRows` builds a `rows` variable that's never read.

## Communication notes
- Hardware mode = design/planning, no code
- Software mode = code generation OK
- DON'T flip into software mode without being told. Wait for the explicit signal even after a long hardware-mode planning thread.
- User holds strong MVC opinions, calls out architectural violations sharply.
- "Dev is where the work gets done; main is the stable baseline."
- One discrete problem per dev cycle. Don't bundle unrelated fixes. (Exception: tightly coupled changes being tested as a bundle.)
- DO NOT pull `main.js` — production bootstrap is `src/scripts/nova-dashboard.user.js`
- **Don't use web_fetch on the repo.** It returns stale or wrong files. ALWAYS read files from the local filesystem. Non-negotiable.
- When asked for "the methods" or edits to a class, prefer separate code blocks per method, not one big dump.
- When asked to edit a class, show edits cleanly without iterating over the same block multiple times. Each block in final form once.
- **NEVER deliver a code edit with `// ... rest unchanged` or any placeholder comment that elides surrounding code.** User pastes verbatim; placeholder comments will break syntax.
- When making CSS changes that depend on Tailwind utilities, prefer owning rules in inline `<style>` blocks. Demo uses a precompiled tailwind.css with explicit safelist — classes not in the safelist produce no CSS.
- **Don't trust the JS console in Tampermonkey for ground-truth diagnostics.** Use the Elements inspector and DOM outerHTML pastes instead.
- Top-level `await` at the browser console is unreliable. Verify via in-code logging or DOM inspection.
- Long conversations degrade assistant accuracy — start fresh between phases.
- **"Blame the cache" is a lazy diagnosis.** Check the live DOM before invoking it.
- **Don't sneak previously-rejected suggestions back in.** Respect "no destroy methods," "inline view is out of scope," etc. decisively across every subsequent code block.
- **When a refactor is ready to commit, take the user at their word about the test plan.**
- **ALWAYS deliver memory files inside a code block.** No exceptions.
